# Tutoring Website

A Flask application for managing tutoring students, lessons, and payments. The
application has separate student and tutor-facing pages; the tutor-facing
management routes are restricted to the email allowlist in
[`app/decorators.py`](app/decorators.py).

## Application structure

- [`run.py`](run.py) creates the application with the factory in
  [`app/__init__.py`](app/__init__.py) and starts Flask's development server.
- [`app/extensions.py`](app/extensions.py) holds the shared SQLAlchemy,
  Bcrypt, and Flask-Login extension instances. The factory initializes them
  for each Flask app.
- [`app/models.py`](app/models.py) defines users, students, lessons, and the
  local mapping between lessons and Todoist tasks.
- `app/<feature>/routes.py` contains Flask blueprints. The factory registers
  authentication, student, lesson, and payment routes under `/auth`, `/students`,
  `/lessons`, and `/payments`; public pages are registered at the site root.
- `app/templates/` contains the Jinja pages, and `app/static/` contains the
  stylesheets served by Flask.
- [`load_db.py`](load_db.py) creates tables for the configured database. It
  does not import or migrate existing data.

## Main data flows

1. Registration creates an unverified `User`. Email verification enables login;
   an authenticated user is associated with a `Student` when the tutor assigns
   the matching email address.
2. The student portal shows scheduled and completed `Lesson` records for the
   associated student. Tutor routes manage student details, plan lessons, and
   mark lessons complete.
3. Creating or editing a lesson persists it in the database and attempts to
   create or update its Todoist task. `TodoistLesson` stores the remote task ID
   associated with that lesson.
4. Tutor lesson tools can import student and lesson information from Google
   Sheets. Recording a completed lesson also writes its details to the lesson
   sheet.
5. The payments pages create Stripe checkout sessions and display payment
   history read from Google Sheets. The Stripe webhook handler records
   successful USD charges in the payment sheet.
6. Lesson suggestions are generated by the Ollama integration using the
   student's general notes and previous lessons.

The Google Sheets, email, Stripe, and Todoist integrations live in the
root-level `*_interactor.py` modules; lesson-suggestion logic lives in
[`lesson_suggestion.py`](lesson_suggestion.py). Route handlers and model
methods call these modules directly; they are not separate services managed by
the Flask factory.

## Local development

Install the pinned dependencies from [`requirements.txt`](requirements.txt),
then prepare the integration credentials needed by the features you want to
run:

- Google Sheets access expects a service-account file named `g_apikey.json` at
  the repository root and access to the spreadsheet configured in
  [`gsheet_interactor.py`](gsheet_interactor.py).
- Email sending reads `GMAIL_TUTORING_APP_PASSWORD`.
- Todoist reads `TODOIST_API_KEY`.
- Stripe reads `STRIPE_API_KEY` and `STRIPE_PAYMENTS_SECRET_SIG`.
- Lesson suggestions read `OLLAMA_API_KEY`.

Initialize the database and start the local server with:

```sh
python load_db.py
python run.py
```

The current factory configures SQLite and a literal Flask `SECRET_KEY`, while
`run.py` enables debug mode. Treat this setup as development-only; production
deployment needs environment-specific configuration and a production WSGI
server.

Run the automated application tests from the repository root with
`python -m pytest -q`. The suite and its coverage boundaries are documented in
[`testsuite/README.md`](testsuite/README.md).
